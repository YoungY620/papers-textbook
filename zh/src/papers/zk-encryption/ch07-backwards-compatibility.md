# 攻击四 — 向后兼容

向后兼容是第四类、也是最后一类攻击，讲者认为它是这几类里最有意思的一类。讲完共享攻击后，讲者把这一类作为更值得一看的内容端出来，其中 Bitwarden 那一例被称作"海森堡攻击"。Bitwarden 与 Dashlane 多年来都在演进自己支持的密码学原语：加密从 CBC 模式的 AES 转向 AES-CBC-HMAC 这类 AE 方案，密钥派生从 PBKDF2 转向 Argon2d 这类内存困难型 PBKDF；Bitwarden 还通过条目级密钥改善了密钥分离。当前客户端默认只用现代密码学，但仍保留"旧格式"支持，于是敌手能把客户端使用的原语降级、有时还是永久降级，把安全性拉低到它仍支持的最弱算法。

## Bitwarden

最新客户端对所有对称操作默认使用认证加密：AES-CBC 配 HMAC，按"先加密后 MAC"组合，用于在登录时解密从服务器取回的用户密钥，也用于加解密保险库条目。更早的版本用不带 HMAC 的 AES-CBC，不提供完整性保护。为兼容两种格式，每个密文都带一个加密类型属性——type 0 表示 AE，type 1 表示纯 AES-CBC——它前置在密文之前，且不受完整性保护。更早的版本也不用当前的密钥层级，因此若服务器未提供，现代客户端会生成一对新的 RSA 密钥 $(pk', sk')$；若服务器未提供用户密钥密文 $c_u$，客户端就用主密钥 $k_m$ 加密 $sk'$。这两项措施让现代客户端能迁移旧保险库。

### BWb1：已知明文预言器

敌手可以利用密钥对的生成以及对用 $k_m$ 加密的支持，在未知 $k_m$ 的情况下得到已知明文的 AES-CBC 密文。登录时它返回空的 $c_u$ 与空的 RSA 私钥密文 $c_{sk}$：$c_{sk}$ 缺失迫使用户生成新密钥对，而 $c_u$ 也是空的，客户端便用 $k_m$ 以 AES-CBC 加密新私钥得到 $c'_{sk}$，并把 $pk'$ 与 $c'_{sk}$ 发给服务器。由于 $sk'$ 中含有 $pk'$ 的编码，敌手观察加密后的 $c'_{sk}$ 与公开的 $pk'$，就得到一个长度 5 个分组的明密文对。

### BW11：用户密钥覆写

敌手伪造密文 $c_u^{adv}$，使客户端解密得到的用户密钥为 $ku = ku^{enc} \| ku^{mac}$，其中加密半段 $ku^{enc}$ 为敌手所知；两个半段各 32 字节，在 CBC 明文中各占两个分组。敌手用 BWb1 的 5 分组明密文对构造它：通过比特翻转把最后一个分组设为填充分组 $P_5$，使前一个分组 $P_4$ 被打乱而 $P_1$、$P_2$、$P_3$ 保持已知，再把密文标记为 type 0。客户端会接受它为合法用户密钥密文——密文在 $k_m$ 下加密、type 0 走 CBC 解密、去填充成功——并解析出 $ku = ku^{enc} \| ku^{mac}$。由于 $ku^{enc}$ 由 $P_1$、$P_2$ 组成，敌手完全掌握；$ku^{mac}$ 则因 $P_4$ 被打乱而不可知。

敌手由此得知加密全部保险库条目的 $ku^{enc}$，攻击之后新加密的每个条目都失去机密性；完整性则因 $ku^{mac}$ 仍不可知而得以保留。触发条件是用户登录：首次登录会失败并把用户引向迁移页面，而攻击都会在随后一次登录时完成。

### BW12：降级到旧格式

同一种构造还能得到 MAC 半段为空的用户密钥：做法与 BW11 相同，但只用三个分组——$P_3$ 为填充分组，$P_2$ 被打乱——客户端同样会接受。密文过短又触发第二项向后兼容特性：客户端把明文解析为不含"mac"的 $ku = ku^{enc}$，此后所有加密都改用纯 CBC 模式。若启用了条目级密钥，条目加密仍用 AES-CBC 配 HMAC，但如 BW10 所示，敌手能轻易把客户端降级为不使用条目级密钥。

于是加密退化为纯 CBC，攻击之后新加密条目的完整性被轻易破坏，并进一步使填充预言攻击成为可能，彻底破坏保险库机密性。论文没为最后这一点开发 PoC，但 Bitwarden 开发者承认其可行。敌手还知道 $P_1$，因而学到 $ku^{enc}$ 的一半。触发条件同 BW11。

讲者把这一对概括为"海森堡攻击"，因为两个方向不可兼得：注入只有加密密钥的短旧式保险库密钥，客户端见不到 MAC 密钥便退回无认证加密，完整性丢失而机密性（因密钥部分被打乱）得以保留；注入加密半段已知的完整现代保险库密钥，则机密性丢失，而被打乱的 MAC 半段保住了完整性。

## Dashlane

Dashlane 的每笔事务都带一个 payload，用它规定解密内容所用的 KDF、密码算法与工作模式。这里涉及两种格式：KWC3 使用 PBKDF2-SHA1 与 AES-256-CBC；Flexible 带一个格式串，解析后选定 KDF（PBKDF2-SHA256 或 SHA1、Argon2i，或默认的 Argon2d）、其参数、密码算法（只有 AES-256）以及工作模式，其中唯一有文档的是默认的 CBC-HMAC 与 GCM。现代客户端默认使用 Flexible，一旦发现 KWC3 就自动把事务迁移为 Flexible。对旧格式的支持因客户端而异：网页扩展支持，CLI 不支持，因此下面只影响支持旧格式的客户端，PoC 针对网页扩展。

### DLb1、DLb2 与 DL03：填充预言与注入

出乎意料的是，纯 CBC 在 Flexible payload 中仍被接受为一种加密模式，且不触发迁移。这打开了填充预言攻击：敌手可用它在密钥 $k_{cbc}$ 下解密密文（DLb1），或在 $k_{cbc}$ 下加密任意明文（DLb2）。未经优化的速率是每处理一个分组需 14 天。DL03（条目注入）用 DLb2 伪造任意事务。三者的完整描述只出现在扩展版本中。

### DL04：移除 KDF 迭代次数

用户设置决定所有新事务 payload 用哪个 KDF 及其参数。敌手先用 DL01（事务重放）删除已有的 Setting 事务，把设置拨回已知的干净状态，再用 DL03 伪造一笔新的 Setting 事务；用户下次创建条目时，客户端就用敌手选定的参数从主密码派生密钥。例如把 PBKDF2 迭代次数从默认的 200,000 改成 1，在暴力破解上取得 200,000 倍加速。主密码的暴力破解成本随之下降，一旦成功即可完全控制账户（触发条件为 DL01 与 DL03）。

### DL05：纯 CBC 降级

这条 Setting 事务还控制今后事务的密码算法与工作模式。与 DL04 同理，敌手伪造设置强制使用纯 CBC，于是客户端一律以纯 CBC 写入，产生的事务便落入 DLb1 的填充预言。敌手随后能解密攻击完成后产生的全部事务（触发条件为 DL01 与 DL03，外加对每条待解密事务执行一次 DLb1）。

PoC 中伪造的最小 Setting 事务仅 9 个分组长，足以测试 DL04 与 DL05。测试时刻意加速了执行；按正常速率估计需超过 126 天，对一次定向攻击而言虽长却合理。另有 DL06（Lucky 64）推迟到扩展版本，表 1 记其成因为"CBC 支持"、影响为"无暴力破解防护"、准备量为 $10^4$ 次同步。

## 降级为何能够得逞

两款管理器都依据服务器提供、未认证的字段选择代码路径：Bitwarden 依据密文前的加密类型属性，Dashlane 依据 payload 格式串，而这些为携带旧数据而设的迁移机制也正是降级的杠杆。客户端无状态，只能由服务器告知它用哪个版本，于是恶意服务器翻转一个比特就能把任何客户端降级到旧路径。

| 编号 | 名称 | 成因 | 影响 | 交互 | 缓解 |
| --- | --- | --- | --- | --- | --- |
| BW10 | 禁用条目级密钥 | 缺乏认证加密 | 降级密钥层级 | 2 次登录 | KS、AD |
| BW11 | 用户密钥覆写 | CBC 支持 | 机密性丧失 † | 2 次登录 | AE |
| BW12 | 降级到旧格式 | CBC 支持 | 保险库完全失陷 † | 2 次登录 | AE |
| DL03 | 条目注入 | CBC 支持 | 保险库完整性丧失 | $10^4$ 次同步 | AE |
| DL04 | 移除 KDF 迭代次数 | CBC 支持 | 无暴力破解防护 | $10^5$ 次同步 | AE |
| DL05 | 纯 CBC 降级 | CBC 支持 | 机密性丧失 † | $10^5$ 次同步 | AE |
| DL06 | Lucky 64 | CBC 支持 | 无暴力破解防护 | $10^4$ 次同步 | AE |

带 † 的仍是能恢复加密密码的攻击。这一类按其收获分成两半：DL03 与 DL04 只破坏完整性或暴力破解防护，本身不解密任何东西；BW11、BW12、DL05 最终都落到机密性丧失（BW11 直接发生，BW12、DL05 经由纯 CBC 降级打开的填充预言）。BW12 与 DL05 波及最广，都是保险库完全失陷：一旦客户端改用纯 CBC 写入，此后每个条目都能通过预言读出。缓解一栏指向同一个根因——这些攻击全都利用了对 AES-CBC 的支持——因此用 AE 取消对无完整性方案的支持才是根本对策；BW10 另需密钥分离（KS）与设置的认证（AD）。

## 本章要点

- Bitwarden 与 Dashlane 都为 AES-CBC 和旧密钥层级保留旧格式支持；Bitwarden 的加密类型属性（type 0 为 AE，type 1 为纯 AES-CBC）前置在密文前且不受完整性保护，正是降级所扳动的杠杆。
- BWb1 利用生成新 RSA 密钥对的迁移路径，在未知主密钥 $k_m$ 下取得一个 5 分组的明密文对。
- BW11 伪造出加密半段为己所知的用户密钥，牺牲此后所有条目的机密性而保住完整性；BW12 伪造出没有 MAC 半段的短密钥，强制纯 CBC，直接破坏完整性、打开填充预言，并暴露 $ku^{enc}$ 的一半。
- 在 Dashlane 中，纯 CBC 仍被 Flexible payload 接受且不触发迁移，由此得到 DLb1、DLb2 预言与 DL03 条目注入；DL04 与 DL05 则借助 DL01 和 DL03 改写 Setting 事务，把 PBKDF2 迭代次数从 200,000 降到 1。
- 由于客户端无状态、只能从未认证的服务器字段得知所用格式，对策是直接取消旧路径，而非去检测它们。
