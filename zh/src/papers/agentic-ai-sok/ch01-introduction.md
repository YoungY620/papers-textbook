# 为什么智能体安全是一个系统问题

智能体 AI 系统的兴起，标志着 AI 领域的一次范式转变：从孤立的大语言模型，转向把大语言模型（LLM）与各种软件组件组合在一起的集成系统。这类混合系统把 AI 模型与传统符号软件放进同一个整体，正是这种组合让它们能够自主执行任务、动态调用工具，而不像独立模型那样只能一问一答。它们的应用已经覆盖从软件开发 [28, 44] 到网页浏览器操作 [99, 108] 的多个方向。本书所说的**智能体 AI 系统**（agentic AI system）与**AI 智能体**（AI agent）指同一种对象；本书所系统化的那项工作把这两个词互换使用，本书沿用这一约定。

让这类系统有用的灵活性，同样让它们危险，而失败案例是具体的、不是假设的。提示注入已被用来访问私有的 GitHub 仓库 [54]，远程代码执行漏洞使攻击者获得未授权的系统访问 [88]。数据外泄攻击通过恶意文档附件和邮件转发泄漏敏感信息 [112, 117]。已有服务器暴露了用户的聊天记录和凭据数据 [98, 115]，攻击者也能利用网页智能体闯入用户的个人银行账户 [13]。

这些事件并非互不相干的漏洞，它们有共同的成因：让智能体系统强大的灵活性与自动化，正是让它面临的安全性挑战从根本上区别于传统软件系统和独立 AI 模型的那组性质。差别是结构性的。单独的语言模型只接收文本、输出文本，它不持有凭据、不读取不受信任的文件、也不写入任何外部服务；智能体三件事全都做，于是模型的一次误判或一次被操纵的输出，会被变成真实世界里的动作。因此只把模型加固好是必要但不充分的：风险存在于各部分如何组合、如何相互作用，而不在任何单独一个部件里。分析的单元必须是整个系统。

既有工作没有这样看待问题。这一领域的文献综述主要聚焦 LLM 安全 [49, 58, 81, 138]，而少数确实讨论智能体的近期综述，也大多集中在特定攻击向量或孤立的系统组件上 [52, 138, 155]。社区缺少的是对智能体系统整体风险的系统性视角，以及由此推出的安全原则与机制指南。本书针对这一缺口，给出对智能体 AI 系统安全图景的首个系统性知识梳理。它从整体的系统视角切入，考察 LLM 与传统软件的组合如何产生单靠组件级防护无法解决的挑战：先刻画影响安全属性的智能体设计维度，再给出覆盖整个智能体生态的攻击向量与安全风险分类，最后讨论智能体的防护原则并系统综述现有防护机制。

这套梳理有三项贡献。

其一，智能体设计维度。一个系统性框架用七个关键设计维度刻画智能体 AI 系统：输入信任、访问敏感性、工作流、动作、记忆、工具、用户界面。对每个维度，它分析该维度上的灵活性如何影响安全风险；七个维度共同构成后续全部分析所围绕的轴线。

其二，完整的攻击图景与分类。攻击向量按威胁模型组织——外部对手、用户级对手、内部对手——安全风险则被归类为覆盖用户交互、模型行为、记忆系统、工具集成与环境交互的若干类别。分类给出了六个攻击向量 V1 至 V6，并把风险记为 R1 至 R7（详见第 4、5 章）。需要说明的是，引言把这组风险称作“九类安全风险”，而分类本身列出的是七类，即 R1–R7；从分类的一致读法看，七类才成立。

其三，防护图景的系统化。现有防护机制被归入三类加以综述——运行时防护、安全设计、组件加固——并指出每种防护针对哪些设计维度、当前防护的局限以及仍然开放的挑战。

支撑这套框架的综述覆盖 128 篇论文，其中 51 篇提出攻击方法、60 篇提出防护方法，其余工作同时涉及攻击与防护，或属于不提出新方法的案例研究。第 2 章会完整交代其方法。

两组比较界定了问题的边界。相对 LLM 安全，智能体安全增加了“触及面”：自主性与环境访问把本属于模型行为层面的风险放大——越狱或幻觉会变成数据外泄或对系统的意外操纵。相对传统软件安全，智能体安全引入了一个不遵循固定程序逻辑的部件：智能体的控制流在运行时生成，无法像源码那样被审计，其数据流也不受传统程序里类型系统和访问控制的约束。两组比较指向同一结论：智能体安全不是模型安全的放大版，也不是“多接了一个新服务”的普通应用安全，而是一个系统问题，它要防的缺陷恰恰出现在组件之间的接缝处。

## 本章要点

- 智能体 AI 系统把 LLM 与传统软件组件组合在一起，“智能体 AI 系统”与“AI 智能体”在本书中互换使用。
- 已有真实事件包括提示注入访问私有 GitHub 仓库、远程代码执行、经恶意文档与邮件转发造成的外泄、聊天与凭据数据暴露，以及网页智能体访问用户银行账户。
- 智能体安全之所以不同于 LLM 安全和传统软件安全，是因为自主性与环境访问会把模型错误变成真实动作，且控制流在运行时生成而非写死在代码里。
- 既有综述要么聚焦 LLM 安全、要么聚焦孤立组件，留下的缺口是对智能体风险与防护的系统级视角。
- 本工作有三项贡献：七个设计维度、按威胁模型组织的攻击分类、分三类的防护图景。
- 该框架建立在 128 篇论文之上，其中攻击方法 51 篇、防护方法 60 篇。
