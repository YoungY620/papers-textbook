# 安全设计

安全设计（secure by design）在架构层面确立安全属性，依靠基础设计原则让智能体本身变得安全，而不是靠过滤流经它的数据。这类机制取决于系统的构建方式，而智能体又与传统的软件系统有本质差别，因此安全设计天然是智能体特有的：它无法直接从传统软件的安全工程中照搬。图 4 把它放进更大的图景里，与运行时防护、身份与访问管理、组件加固并列。

## 权限分离

遵循最小权限原则，传统安全通过给不同软件组件分配不同的权限级别来实现权限分离，早期的自动化尝试就是如此。在智能体中，这一思路延伸到给各个组件分配权限并加以隔离，从而把系统整体风险降到最低。权限分离通过把不可信数据与做决策的组件隔开，缓解错误指令跟随（R2）；通过在不同信任级别的组件之间强制划界，缓解不受约束的数据流（R3）。

### 代表性工作

AirGap 对 LLM 的执行做拆分：先在内存中只保留与任务相关的数据，再用这份被最小化的内存去完成任务，避免执行过程中暴露敏感数据。f-secure LLM、Camel 与 FIDES 把 LLM 的操作拆成工具调用规划与工具结果解析两部分；由于工具结果不再直接喂给规划，外部数据也就无法左右智能体的决策。PFI 把工具与环境分成普通版和沙箱版，按数据信任级别切换执行权限。IsolateGPT 面向移动系统做按应用粒度的权限分离，为每个应用派生专属智能体，让它只与应用自己的工具和资源交互，从而防止跨应用利用。

### 设计维度

权限分离的设计沿两个轴向变化。

- 权限分离策略。纵向权限分离实现分层权限，类似内核与用户态的划分，规划器与解析器的分离就是把工具调用规划与工具结果解析隔开。横向权限分离则让多个子智能体在互不相交的访问范围上并行运行，IsolateGPT 为每个应用派生的智能体只接触本应用的工具和资源，即属此类。
- 分离范围。被分离的组件因系统而异。LLM 本身可以拆成规划与解析两个进程，使工具结果无法直接影响规划决策；内存分离创建彼此独立的内存空间，把敏感数据与低权限组件隔开；外部环境则可以复用已有的沙箱机制，例如计算机系统中的容器化技术和 Web 服务中的细粒度访问控制。

### 局限与开放挑战

当前的权限分离研究主要针对简化环境中的通用间接提示注入，往往难以应对真实环境的多样而复杂的风险，例如 Web、文件系统与数据库，它们需要专门的分离策略。权限分离还会带来效用损失，因为把功能拆散到相互隔离的组件会割裂智能体的能力。如何把一个智能体划分成一组有效的最小权限组件仍然是开放问题；设计隔离组件之间高效的通信，既降低效用损失又保住安全保证，是实际部署中持续的挑战。

## 可证明安全与形式化验证

传统安全用形式化验证为正确性与安全性给出理论证明。在智能体系统中，形式化验证转为：对智能体的随机行为建立形式模型，并在动态的使用语境中定义可验证的性质。

### 代表性工作

面向智能体的形式化验证仍是一个很新的领域，已有工作非常有限。VeriSafe Agent 是为数不多较为成熟的方法之一：它为移动 GUI 智能体建立形式规约，并验证其行为是否与用户最初的意图一致。

### 设计维度

形式化验证方法在形式化对象与安全属性两方面有所不同。

- 形式化对象。VeriSafe Agent 把用户意图形式化为一个作用于 UI 状态迁移的领域特定语言，在执行前验证候选的 GUI 动作是否与用户任务一致。Formal-LLM 把开发者定义的规划约束（如工具调用顺序）编码为下推自动机，以约束规划生成，保证其合法且可执行。ShieldAgent 把外部政策文档（如法规或企业内部规则）结构化为作用于动作轨迹的声明式规则电路，用来强制政策合规与安全。
- 安全属性。语境安全保证智能体始终与用户意图和系统政策保持一致；安全性属性验证保证其动作不违反预定义的安全约束、不造成有害后果；正确性属性验证保证其行为符合指定的功能需求并产生预期输出。

### 局限与开放挑战

传统的形式化方法面向用结构化语言写成的程序，而基于 LLM 的智能体运行在概率模型之上。这一根本差异使得为智能体建立既能刻画随机行为、又能保住有意义安全保证的形式模型十分困难。此外，智能体与 Web、文件系统或移动应用等各种环境交互时的安全属性仍未得到充分刻画。能够覆盖智能体安全需求全谱的形式化验证框架，大体上仍是一个开放挑战。归根结底，难点在于系统的核心是概率分布而不是程序：一个足够完备因而有用的模型必须描述模型输出是如何分布的，而我们想陈述的保证针对的却是在特定语境下采取的单个动作。

## 本章要点

- 安全设计在架构层面起作用，而不是靠过滤数据流；它对架构的依赖使它成为智能体系统特有的防护类别。
- 权限分离通过把不可信数据与决策组件隔开缓解 R2，通过在不同信任级别组件之间强制划界缓解 R3。
- 纵向分离是分层的，如规划器与解析器的拆分；横向分离让多个子智能体在互不相交的访问范围上并行，IsolateGPT 按移动应用派生智能体即为例证。
- 分离会牺牲效用；最小权限的分解方式以及隔离组件之间的通信，都仍是开放问题。
- 面向智能体的形式化验证是已有工作极少的全新领域，VeriSafe Agent、Formal-LLM 与 ShieldAgent 在形式化对象和所声明的安全属性上各不相同。
- 验证的开放挑战在于：智能体建立在概率模型之上，形式模型必须刻画随机行为，同时仍能给出有意义的保证。
