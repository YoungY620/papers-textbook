# 安全目标与运行时防护

智能体防护按两个维度归类：所服务的安全目标与介入时机。安全目标是机密性、完整性、可用性，外加智能体特有的上下文安全。运行时防护在执行期间动态施加安全约束，含五类机制——输入护栏、输出护栏、信息流控制与污点追踪、监控、人在回路验证；表 2 列出各机制及覆盖的风险 R1–R7，图 4 标出各自针对的组件或控制流阶段。

## 安全目标

### 机密性

机密性要求信息只能被授权实体访问：API 密钥等系统级机密、智能体内部记忆、用户私有数据，以及模型参数与系统提示等 LLM 相关数据。它对应不受约束的数据流（R3）与私有数据泄露（R5）。

### 完整性

完整性要求智能体系统与外部环境中的数据保持可信、不被未授权实体修改：防止对智能体记忆、LLM 输出、工具结果与环境数据的篡改，也防止智能体被恶意指令操纵而执行非预期动作。其具体目标随智能体的组件及其数据流、控制流而不同，对应 R1、R2、R3、R4 与 R6。

### 可用性

可用性防止 LLM 推理与工具调用消耗用户资源造成的资源滥用：防止 token 被耗尽，并保护外部系统与智能体宿主免受拒绝服务。对应 R7。

### 上下文安全

上下文安全确保智能体的上下文与用户意图的任务一致，阻止执行期间操纵上下文的攻击。它规定哪些上下文元素可被接纳——系统提示、用户目标、工具描述、检索片段——及其优先级，从而补充机密性与完整性，避免指令覆盖、上下文漂移与不安全的工具选择。

## 运行时防护

运行时防护在智能体执行期间动态施加安全约束，实时探测威胁与行为。

### 输入护栏

输入护栏在输入到达智能体前校验，作为第一道防线把恶意指令与数据挡在下游组件之外，缓解异构不可信接口（R1）由不可信数据源带来的风险。对独立模型，它检测越狱提示与有害内容；对智能体，它校验检索数据的可信度以应对动态检索与工具执行，例如用 URL 白名单把检索限制在可信来源。NeMo Guardrails 提供领域特定语言定义输入过滤器；Constitutional classifiers、llama-firewall、PromptShield 用专用模型检测直接与间接提示注入；DataSentinel 刻意利用对提示注入脆弱的模型识别能绕过其他护栏的隐蔽注入。设计沿三个维度变化：检测机制（基于规则的严格性与基于模型的自适应性）、校验对象（内容语义与来源可信度，后者为智能体动态检索特有）、缓解策略（过滤、清洗，或规范化为带类型与校验的结构）。

局限与开放挑战。输入空间庞大多样，通用判据难以建立：基于模型的检测器会被自适应攻击绕过，基于规则的检测器耗人力且难泛化，误报与漏报因此并存——误报部分源于精度有限，更源于安全与不安全数据之间边界模糊；漏报使攻击者能把恶意输入注入智能体。

### 输出护栏

输出护栏检查智能体对外行为——对用户的回复与触达外部系统的工具调用——拦截表面无害却触发恶意动作的攻击：校验任务对齐缓解 R2，输出验证缓解 R4，检查敏感数据暴露缓解 R5，校验工具使用缓解 R6。面向 LLM 的输出护栏用分类器或可编程规则检测有害输出，智能体特有的则校验工具使用与动作序列以符合上下文相关策略并与用户意图对齐。Progent、Conseca、Agrail 依据运行时上下文生成自适应策略，防止环境数据泄露、损坏与资源耗尽；GuardAgent、ShieldAgent 依据人工策略构建领域特定检查；CodeShield、HeimdallM 对智能体生成的代码做静态分析以防任意代码执行；网络白名单把连接限制在预先授权的域。设计沿检测目标（有害内容、不安全代码、不安全动作、对齐检查、数据隐私、领域策略与上下文安全执行）及检测机制（从基于规则的模式匹配到基于模型的分类器，含结构化策略配合模型的混合方案）变化。

局限与开放挑战。输出护栏同输入护栏一样有误报、漏报及基于规则与基于模型的权衡，但因依赖 LLM 输出且需处理更多数据，消耗更多计算与时间。

### 信息流控制与污点追踪

信息流控制（IFC）与污点追踪限制信息在系统内的流动：经典 IFC 为每份数据从预定义的信息流格分配安全标签、传播标签并检测违反格约束的流动。用于智能体时它针对模型固有的不受约束数据流（R3），并缓解下游的机密性（R5）与完整性（R6）违规。PFI、CaMeL、FIDES 把工具结果转为符号变量以确定性追踪数据流——PFI 防止不可信数据控制工具参数，CaMeL 与 FIDES 防止验证码等凭据到达恶意邮件收件人之类的不可信端点——并常与特权分离配合。宽松信息流控制通过不同输入组合多次推理度量输入对输出的影响；Melon 把该度量扩展到智能体的控制流与数据流，比较有无特定输入时的工具使用并阻断被操纵的工具调用。设计沿安全目标——完整性（阻止不可信输入影响工具调用决策）与机密性（阻止敏感数据到达不可信汇点）——及机制（基于符号变量、基于多次执行、基于模型，后者要求 LLM 依据智能体轨迹检查信息流）变化。

局限与开放挑战。多次执行与变量推理带来可观运行时开销，限制其在对延迟敏感场景的实用性；标签蔓延还可能使智能体不可用，除非有自动且安全的标签降级规则。弥补缺口需要轻量追踪与安全地放宽标签的原则性策略。

### 监控

监控检查输入、输出与中间状态以提供全局可见性，揭示单个动作看似无害、合起来却构成恶意目标的分布式威胁，并观察长周期跨工具与服务的交互，多智能体系统尤其如此。它缓解 R5、R6、R7。AgentMonitor 对网页与文件访问环境中的行为风险打分；AgentAuditor 为不安全动作构建特征记忆以检测运行时异常；SentinelAgent 与 Guardian 通过交互图建模检测多智能体异常。设计沿检测目标（长轨迹上的异常检测与交互图监控）及日志粒度变化：从动作与工具调用的粗粒度汇总到记录中间推理与参数的细粒度轨迹，粒度越细检测越强，但存储、计算与隐私暴露越高。

局限与开放挑战。监控继承了运行时防御的根本局限：不准确与性能开销。随机且依赖上下文的行为使良性动作难以区分于有害动作；静态规则漏掉新型攻击，自适应模型有开销却仍可被规避；长期运行不断累积日志，其存储与隐私控制基本尚待研究。

### 人在回路验证

人在回路验证让用户校验智能体行为与工具使用，给出用户自定义的安全决策控制。它缓解 R5、R6、R7，且相对而言是智能体独有的：智能体代表用户行事并接触文件、网页、第三方工具等外部环境，需要在高风险动作前获得确认。相关文献有限：GitHub Copilot、Gemini Code Assist、Cursor 等编码智能体在写文件或执行命令前请求批准，智能体防御系统在动作违反策略时启用验证。设计沿三个维度变化：验证范围（终端命令、工作区外的文件访问、删除等破坏性动作）、用户提醒（应说明拟执行的动作、相关风险与后果）、重复策略（“仅允许一次”“永不允许”“始终允许”对应移动端权限模式，近期工作建模用户的批准偏好以降低提示频率）。

局限与开放挑战。频繁提示使使用者不堪其扰、产生决策疲劳，反而削弱原本的安全收益；当前提醒也预设了多数用户不具备的安全素养，导致其盲目批准高风险动作或对良性动作过度反应。实用系统需要判据来决定何时交由人类判断，并给出信息充分又轻量的解释。

## 本章要点

- 安全目标是机密性、完整性、可用性，外加上下文安全；后者使智能体上下文与用户意图的任务一致，并规定可被接纳的上下文元素及其优先级。
- 机密性对应 R3 与 R5，完整性对应 R1、R2、R3、R4、R6，可用性对应 R7；上下文安全是对前两者的补充。
- 输入护栏在输入到达前校验并缓解 R1；输出护栏检查对外行为，覆盖 R2、R4、R5、R6；信息流控制与污点追踪针对 R3 并缓解 R5、R6，代价是运行时开销与标签蔓延。
- 监控与人在回路验证都缓解 R5、R6、R7，但各运行时机制覆盖重叠、无一能贯穿 R1–R7，因此需组合使用。
