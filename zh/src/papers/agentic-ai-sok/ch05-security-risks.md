# 安全风险

独立语言模型只有一个交互界面（提示词），智能体则同时暴露多个。§4.2 的风险分类法围绕这些界面组织：每条风险对应攻击者可以瞄准的组件，R1–R7 是本书统一的编号。按保密性、完整性、可用性衡量，分布不均：保密性覆盖 R3 与 R5，完整性覆盖 R1、R2、R3、R4 与 R6，可用性覆盖 R7。

## R1. 异构不可信接口

智能体暴露多种异构接口：它检索的外部数据源、不断累积的持久记忆，以及信任级别各异的第三方工具，每一个都是攻击入口，合起来使攻击面远大于独立模型。攻击面图景中 V1–V6 全部从这些接口进入系统，因此 R1 更像其他风险成立的前提，而非一次具体失败；放大这些接口的设计维度（输入信任、记忆、工具）也同步放大该风险。R1 属于完整性风险：攻击者控制的内容正是经这些接口变成智能体信任的内容。

## R2. 错误指令跟随

智能体跟随攻击者注入的恶意提示，而非良性用户或系统开发者本来的指令。机制是：来自外部或攻击者控制来源的输入会在智能体内部被模型处理，从而影响其行为，这里没有类似“已校验函数参数”的边界。供给它的是提示注入家族：V1 经检索内容的间接提示注入、V4 用户级攻击者的直接提示注入，以及 V6 记忆投毒，其植入的指令可存活到后续会话。工具投毒（V3）是变体，恶意提示可以藏在工具名或描述中。这属于完整性失效。

## R3. 无约束/不安全数据流

大模型因随机性而数据流天然不受约束。在智能体中，数据可从不可信接口（R1）的任意输入自由流向任意输出，无论是用户回答还是随后的工具调用；传统系统依赖编程语言、类型系统和访问控制约束传播。后果是一组衍生风险：私有数据泄露（R5）、数据损坏（R6）与资源耗尽（R7）。典型例子：智能体检索不可信网页内容后，在回答中给出一个可能携带攻击者控制数据的 URL，一旦该 URL 被自动访问便造成外泄，表现为 R5。属此形态的已记录案例有 GitHub Copilot Chat 的提示注入到数据外泄链条，以及 CVE-2025-32711。R3 同时损害保密性与完整性。

## R4. 幻觉与模型错误

模型会生成不正确的内容，这一问题在智能体与环境的交互中更严重，因为智能体会对幻觉内容采取行动：后果不再是错误信息，而是现实效果，例如访问攻击者控制的资源。攻击者借“包幻觉”把它变成可复现手法：注册与代码生成模型频繁幻觉出的名称相同的恶意软件包，该现象已有 USENIX Security 2025 的大规模分析。模型局限由此成为可靠的代码注入与供应链向量，与恶意数据注入（V2）同类。R4 损害完整性。

## R5. 私有数据泄露

智能体同时在多个组件上处理敏感数据——用户对话、持久记忆、工具凭据与环境资源——未授权访问的机会因此来自组件间的交互，而非单个组件的缺陷。模式包括：操纵智能体把数据发往攻击者控制的服务器；通过自动 URL 访问让数据经请求参数泄露；以及滥用领域特定漏洞（SSRF、XSS、路径穿越、SQL 注入）触达受保护资源。近期事件都是真实的保密性违规：Mozilla 基金会推动 Meta 停止意外分享私有 AI 对话、2023 年 3 月 20 日 ChatGPT 故障的复盘，以及可能导致 API 密钥被窃取、大模型响应被劫持的 LangSmith 智能体漏洞。R5 是保密性失效，也是 R3 最直接促成的风险。

## R6. 非预期/未授权操作与数据损坏

完整性可被两种密切相关的途径破坏——非预期与未授权操作、数据损坏——二者同属一个编号，因为它们都是对内外状态的未授权修改。非预期操作造成不可逆的状态变更，如未授权购买或任意代码执行；数据损坏直接改动存储资源，如文件或数据库。所处层不同，症状也不同：用户界面层可能给出虚假或误导性信息；记忆层可能被注入投毒知识或恶意指令而污染后续行为（被引实例是投毒智能体记忆或知识库的红队研究）；环境层则可被命令注入、SQL 注入或文件系统操纵驱动去做未授权修改。R6 属于完整性失效。

## R7. 资源耗尽与拒绝服务

智能体消耗计算资源、API 调用和与外部系统的交互，其自主性使攻击者能把这种消耗转向运营方：昂贵的 API 调用、被迫的无限循环或过度内存占用造成拒绝服务，使智能体及其触及的系统不可用，或在经济上难以为继。R7 是可用性风险，衡量偏经济而非仅偏运行。

## 智能体系统中的其他风险

上述风险损害的是用户或周边环境。第二类风险瞄准智能体系统本身：窃取编码专有知识的系统提示、工具描述与配置，受害方是智能体开发者与工具提供方而非最终用户。可观察行为是另一条渠道：工具执行耗时、API 调用序列与网络流量模式构成智能体侧信道。文本生成图像模型与现实世界提示词服务上的提示窃取攻击（均发表于 USENIX Security）是最接近的前人工作；尚无研究考察这类侧信道攻击，分析留待后续工作。

## 从设计维度到风险

![Relationship between agent design dimensions and risks.](assets/fig3-dimensions-risks.png)

图 3 的映射说明智能体安全不能按组件分别处理，其统领观察是灵活性越高风险越大。输入信任、记忆、工具直接驱动 R1：扩展外部数据源使间接提示注入成为可能，引入持久记忆创造记忆投毒目标，接入第三方工具带来供应链风险。

工作流维度主要驱动模型风险 R2、R3、R4。工作流从简单聊天机器人转向大模型定义的动态执行后，灵活控制流给劫持智能体推理更多机会，使错误指令跟随与无约束数据流更严重；智能体动态选择工具与资源时幻觉风险被放大，因为错误输出会直接触发现实动作。

访问敏感度、操作、用户界面决定后果类风险 R5、R6、R7 的严重程度，而非它们是否发生。数据越敏感，违规影响越大：被攻陷的智能体可以泄露、损坏或耗尽更有价值的资源；操作能力从仅返回响应扩展到执行，会把信息泄露变成环境破坏；复杂用户界面再打开新渠道：自动 URL 访问（保密性）、执行破坏性命令（完整性）、界面操纵（可用性）。

## 风险交互与放大

R1–R7 以级联方式相互作用：初始失效在组件间传播并放大为系统级威胁。攻击面扩大（R1）增加攻击者控制数据的入口，使恶意输入触达并利用模型风险（R2、R3、R4）；经外部数据的间接提示注入可触发错误指令跟随，进而改写智能体行为。模型风险再放大后果类风险（R5、R6、R7）：错误指令跟随导致数据外泄（保密性）、数据损坏（完整性）或资源过度消耗（可用性）。无约束数据流同时抬高保密性与完整性风险，既让数据泄露成为可能，也让恶意代码得以执行；幻觉使智能体在伪造资源上操作，抬高完整性风险。因此只针对单个组件的防护无法切断级联链条，防护必须在系统层面纵深防御。

附录把 MITRE ATLAS 威胁矩阵中与智能体相关的条目映射到本书的向量与风险分类。向量一侧：V5 对应 Poison Training Data、Publish Poisoned Datasets、Publish Poisoned Models；V6 覆盖 RAG Poisoning、False RAG Entry Injection、AI Agent Context Poisoning；V4 即 LLM Prompt Injection；V1 覆盖 Retrieval Content Crafting、Drive-by Compromise、Prompt Infiltration via Public-Facing Applications。风险一侧：R2 对应 AI Agent Tool Invocation；R5 覆盖 Credentials from AI Agent Configuration、OS Credential Dumping、RAG Credential Harvesting、Unsecured Credentials、LLM Response Rendering；R6 覆盖 Modify AI Agent Configuration、LLM Trusted Output Components Manipulation、External Harms；R7 对应 Denial of AI Service 与 External Harms，后者与 R6 共用。

## 本章要点

- 分类法把七条风险对应到攻击者可瞄准的组件，一次事件常触发其中多条。
- R1 是前提而非事件本身：V1–V6 全部经某个异构不可信接口进入系统，提示注入家族（V1、V4、V6 植入的指令）驱动 R2。
- R3 是不可信输入到任意输出的无约束传播，R4 通过包幻觉把模型错误变成代码注入与供应链攻击。
- R5 是 R3 最直接促成的保密性风险，R6 是涵盖非预期操作与数据损坏的完整性风险，R7 是可用性风险。
- 系统提示、工具描述与配置本身就是攻击目标；工具执行耗时、API 调用序列、网络流量模式等侧信道尚无前人研究。
- 灵活性放大风险，风险从 R1 经模型风险级联到后果类风险，仅靠组件级防护并不充分。
