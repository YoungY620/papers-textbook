# Why agent security is a systems problem

The advance of agentic AI systems marks a paradigm shift in the AI landscape: away from isolated language models and toward integrated systems that combine one or more Large Language Models (LLMs) with diverse software components. These hybrid systems put AI models and traditional symbolic software into a single artifact, and that composition is what lets them execute tasks autonomously and use tools dynamically. They already span applications from software development [28, 44] to web browser use [99, 108]. An **agentic AI system** and an **AI agent** name the same object here; the work this book systematizes uses the two terms interchangeably, and so does this book.

The flexibility that makes these systems useful also makes them dangerous, and the failures are concrete rather than hypothetical. Prompt injection attacks have been exploited to reach private GitHub repositories [54], and remote code execution vulnerabilities have enabled unauthorized system access [88]. Data exfiltration attacks have compromised sensitive information through malicious document attachments and through email forwarding [112, 117]. Servers have exposed user chat and credential data [98, 115], and attackers have gained access to users' personal banking accounts by exploiting web agents [13].

These incidents are not unrelated bugs. They share a cause: the flexibility and automation that make agentic systems powerful are the same properties that create security challenges fundamentally different from those of traditional software systems and from those of standalone AI models. The difference is structural. A language model alone receives text and emits text: it holds no credentials, reads no untrusted file, and writes to no external service. An agent does all three, and the combination turns a mistaken or manipulated model output into a real-world action. Securing the model is therefore necessary but not sufficient, because the risk lives in how the parts combine and interact, not in any single part. The unit of analysis has to be the whole system.

Existing work does not treat it that way. Literature reviews in this area focus primarily on LLM security [49, 58, 81, 138], and the few recent surveys that do address agents largely concentrate on specific attack vectors or on isolated system components [52, 138, 155]. What the community lacks is a systematic view of the overall risks of the agentic system as a whole, together with guidance on the security principles and mechanisms that apply to it. This book addresses that gap by providing the first comprehensive systematization of knowledge on the security landscape of agentic AI systems. It approaches agent security from a holistic systems perspective, examining how the combination of LLMs with traditional software creates security challenges that component-level defenses alone cannot address. The analysis begins with a systematic characterization of the agent design dimensions that influence security properties, continues into a taxonomy of attack vectors and security risks across the entire agent ecosystem, and ends with the defense principles for agents and a survey of existing defense mechanisms.

The systematization makes three contributions.

First, agent design dimensions. A systematic framework characterizes agentic AI systems through seven key design dimensions: input trust, access sensitivity, workflow, action, memory, tool, and user interface. For each dimension it analyzes how flexibility along that dimension changes the security risk, and the seven dimensions together form the axis along which the rest of the analysis is organized.

Second, a comprehensive attack landscape and taxonomy. Attack vectors are organized by threat model — external adversaries, user-level adversaries, and internal adversaries — and the security risks are classified into categories that span user interaction, model behavior, memory systems, tool integration, and environment interaction. The taxonomy enumerates six attack vectors, V1 through V6, and expresses the risks as R1 through R7 (Chapters 4 and 5 give both). The Introduction calls these "nine security risk categories" while the taxonomy itself lists seven, R1–R7; the seven-risk reading is the one the classification supports.

Third, a defense landscape systematization. Existing defense mechanisms are surveyed in three categories — runtime protection, secure-by-design, and component hardening — and the survey identifies the specific design dimensions each defense targets, the limitations of current defenses, and the open challenges that remain.

The review behind this framework covers 128 papers, of which 51 contribute attack methods and 60 contribute defense methods; the remaining works address both attacks and defenses, or are case studies that introduce no new method. Chapter 2 sets out the methodology in full.

Two comparisons fix the boundary of the problem. Against LLM security, agent security adds reach: autonomy and environment access magnify risks that begin as model behavior, turning a jailbreak or a hallucination into data exfiltration or unintended system manipulation. Against traditional software security, it adds a component that does not follow fixed program logic. An agent's control flow is generated at run time, so it cannot be audited the way source code is, and its data flow is not constrained by the type systems and access controls that regulate a conventional program. Both comparisons point the same way. Agent security is not a larger version of model security, and it is not ordinary application security with a new service in it; it is a systems problem, and the defects it has to prevent are the ones that appear in the seams between components.

## Key points

- An agentic AI system combines LLMs with traditional software components, and the terms "agentic AI systems" and "AI agents" are used interchangeably.
- Real incidents already include prompt injection reaching private GitHub repositories, remote code execution, exfiltration through malicious documents and email forwarding, exposed chat and credential data, and web-agent access to users' banking accounts.
- Agent security differs from LLM security and from traditional software security because autonomy and environment access turn model errors into real-world actions, and because control flow is generated at run time instead of being coded.
- Existing reviews cover LLM security or isolated components, leaving a gap: a systematic, system-level view of agent risk and defense.
- The work's three contributions are seven design dimensions, an attack taxonomy organized by threat model, and a defense landscape in three categories.
- The framework rests on a review of 128 papers, with 51 attack methods and 60 defense methods.
